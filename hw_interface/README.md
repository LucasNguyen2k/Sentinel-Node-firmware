# HW Interface (Edge HAL)

Turns the SN Device Driver's data (`server/sentinel_node_api.py`) into the Edge HAL interface agreed with the
software team: files in the **data area** and messages on **MQTT `sentinel/v1`** (see the *Edge HAL Proposal*).

| Dataset | Produced from | Output |
| --- | --- | --- |
| NODE-01..04 | Registration + `CONFIG`; again on a new boot, firmware or `config_set` | `sentinel/v1/{id}/birth` (retained) |
| Heartbeat | Each new node status; `online: false` when the driver reports the node offline | `…/heartbeat` |
| CHEM-01 | Latest record + status, every `HWI_CHEM01_S` (120 s) | `…/data/CHEM-01` |
| CHEM-02 / CHEM-03 | Records during an event, one CSV per `HWI_PART_S` (30 s); event state changes | `…/file/CHEM-02`, `…/event/CHEM-03` |
| ACO-01 | 5 s cut from the driver's audio recording, every 5 min | `…/file/ACO-01` |
| ACO-02 / ACO-03 | 30 s parts during an event or a `record_audio` command | `…/file/ACO-02`, `…/event/ACO-03` |
| IMG-01 | Newest periodic picture, every 5 min | `…/file/IMG-01` |
| IMG-02 / IMG-03 | Event pictures, `CAPTURE` every 60 s during an event, at least 2 per event, `capture_image` | `…/file/IMG-02`, `…/event/IMG-03` |
| Commands | `capture_image`, `record_audio`, `stop_recording`, `config_set` (allowed keys only) | `…/cmd_result` |

Identifiers: `device_id` = `SN-<MAC>`, `event_id` = `<device_id>-<node event>`, `boot_id` = `b<boot count>`,
`seq` per device and dataset (kept in SQLite across restarts). File names: UTC start time with microseconds.
Files are written as `.part` and renamed before their "file ready" message; kept `HWI_RETENTION_S` (24 h).

Schemas (the contract): `interface/schemas/sentinel-v1/`, generated by `interface/make_schemas.py`.

## After a server outage

The node sends an event message once; if the server is unreachable it is lost (the event is still written to
the node's own event log). When a node comes back, the HW Interface waits until its buffered records have been
replayed, reads `LOG 50`, and publishes every event it never saw live as CHEM-03 with `"late": true` and
`"source": "node_event_log"`, with CHEM-02 files built from the replayed records (also `"late": true`). A live
event whose end fell into the outage is closed the same way. Events already handled are kept in the HW Interface's state store, so a
restart never publishes them twice; on the first contact with a node, its existing log is only recorded.
Pictures and sound from an outage exist only on 32 MB boards; the birth message's `storage` block tells the
software team what each node keeps (16 MB: records for about 40 minutes, no pictures, no sound clips).

## Run

```bash
python3 -m hw_interface          # settings from HWI_* environment variables, see config.py
```

On the Edge Server it runs as the systemd unit `sentinel-hw-interface` (installed by `ci/setup_agent.sh`,
settings in `/etc/sentinel-hw-interface.env`).

## Test

```bash
python3 -m pytest tests/hal -v   # Mosquitto + driver + emulated node + HW Interface + node-gateway emulator
python3 tests/common/node_gateway_emu.py --data-root /var/lib/sentinel/data-area --show   # watch a live system
python3 tests/common/node_gateway_emu.py --data-root /var/lib/sentinel/data-area \
        --send capture_image --device SN-00E04C0F5C9D --args '{"count": 2}'              # send one command
```

## Not yet (firmware step)

Until the firmware sends them, milliseconds are synthetic (+50 ms per record within a second), `boot_id` is the
boot count at arrival, and the gas voltage uses the ADC settings in `HWI_ADC_*` (today 10-bit over 3.3 V).
Audio is cut from the driver's continuous one-minute recordings; capture on demand is the next driver change.
